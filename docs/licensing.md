# Strazh Pro licensing (v1)

Strazh is free to download, scan, and get AI suggestions. **Apply fix** (the one-click
local manifest edit, with Undo) is gated behind a **Pro** license. Validation is fully
**offline** — no server, no account, no network call.

This document is for whoever runs the business: how keys work, how to issue them, how to
test the flow, and the honest security limits.

---

## 1. Key format

A license key is a tiny signed token (JWT-like):

```
SZ1-<base64url(payload_json)>.<base64url(hmac_sha256(payload_segment))>
```

- `payload_json` is `{"name": "<who>", "plan": "pro", "exp": <unix_secs | 0>}`.
- `exp == 0` → perpetual. Otherwise it's a Unix expiry timestamp (seconds).
- The signature is **HMAC-SHA256** over the base64url payload *segment string*, using a
  secret embedded in the app binary.
- Only `plan == "pro"` unlocks Apply fix.

Implementation: [`src-tauri/src/license.rs`](../src-tauri/src/license.rs). It uses the
`sha2` crate the project already depends on (HMAC and base64url are hand-rolled — no new
dependencies).

---

## 2. Generating keys (after someone pays)

Use the `keygen` binary (it links the same signing code the app validates with):

```bash
# Perpetual Pro key for a buyer (use their order id / email as the name):
cargo run --bin keygen --manifest-path src-tauri/Cargo.toml -- --name "order_12345" --plan pro

# A 1-year subscription key (expires 365 days from now):
cargo run --bin keygen --manifest-path src-tauri/Cargo.toml -- --name "order_12345" --plan pro --days 365

# Print the standard set of test keys:
cargo run --bin keygen --manifest-path src-tauri/Cargo.toml -- --test
```

The command prints the key (and a `valid=true/false` self-check). Email that string to the
buyer. They paste it into the app: **About → License → Activate**.

> Billing is out of scope for v1. Hook the checkout (Stripe Payment Link / Lemon Squeezy)
> to any workflow that lands you the buyer's email + order id, then run `keygen` and send
> the key. The checkout link lives in `website/index.html` (search `REPLACE_ME`).

## 3. Validating / how the app checks

On launch and whenever the License dialog changes, the app calls the Rust command
`license_status`, which:

1. reads the stored key from the per-user config file, then
2. checks the `SZ1-` prefix, recomputes the HMAC and compares it in constant time, decodes
   the payload, and rejects anything expired.

The stored key lives next to the Nebius credential, one documented file:

- Windows: `%APPDATA%\com.strazh.app\license.key`
- macOS: `~/Library/Application Support/com.strazh.app/license.key`
- Linux: `$XDG_CONFIG_HOME/com.strazh.app/license.key` (or `~/.config/...`)

Apply fix is enforced in **two** places (defense in depth): the UI hides/locks the button
for Free users, and the Rust `apply_manifest_fix` command refuses to write unless a valid
Pro key is stored.

## 5. Honest security note

This is a **good-faith gate, not copy protection.** The HMAC secret ships inside the
desktop binary, so a determined user can extract it and mint their own keys. That's an
accepted trade-off for v1: it keeps honest users honest with no server, accounts, or
telemetry.

**Rotating the secret:** change `LICENSE_SECRET` in
[`src-tauri/src/license.rs`](../src-tauri/src/license.rs) and rebuild. All previously
issued keys stop validating (you'd re-issue them).

**When you outgrow this:** move signing to a licensing server and keep only a *public*
verification key in the app, or validate keys against a lightweight activation endpoint.
Either is compatible with the current `SZ1-` shape — only the trust root changes.
